# BioDataQC

**Sequencing-delivery validation, quality-control review, and traceable reporting.**

BioDataQC is an independent **Python / Streamlit prototype** for inspecting biomedical sequencing data deliveries. It checks configured metadata and FASTQ requirements, explains structural failures, preserves validation history in SQLite, and prepares verifiable delivery packages. An optional integration displays sequencing-quality measurements from **FastQC 0.12.1**.

> **Français :** BioDataQC est un prototype personnel de contrôle qualité des livraisons de données de séquençage : validation des FASTQ et métadonnées, détection des incohérences, traçabilité SQLite, rapports et préparation de livrables vérifiables. Il s'agit d'un projet personnel et indépendant.

## Why this project?

A sequencing delivery can contain missing or mismatched read pairs, malformed FASTQ records, metadata inconsistencies, or altered files. BioDataQC turns configured checks into an inspectable workflow: **load → validate → investigate → compare → report → package → verify**.

### Key features

- **Delivery inventory:** expected versus present files, samples and metadata.
- **Structural validation:** configurable rules for sample metadata, file naming, R1/R2 pairing, FASTQ record structure, quality encodings and integrity references.
- **Actionable findings:** READY / BLOCKED / INCOMPLETE status with per-check reasons and next actions.
- **Sequencing-quality review:** optional FastQC results with per-module PASS / WARN / FAIL, plots, and original HTML / ZIP artifacts.
- **History & comparison:** saved SQLite validation runs and before/after comparisons for corrected deliveries.
- **Reporting & packages:** JSON/HTML evidence and copied input packages that can be checked against the validated snapshot.

**Important:** `READY` means the configured **structural** checks passed for an observed input snapshot. It does **not** certify biological quality, clinical suitability, or acceptance by a sequencing laboratory. FastQC quality flags are separate from the structural readiness decision.

## Run locally

**Requirements:** Python 3.12 and a supported Python environment; Streamlit for the interface. FastQC (with Java) is **optional** and only needed to run the *Sequencing quality* analysis.

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Open the local URL shown by Streamlit (normally `http://localhost:8501`). In the sidebar choose **Clean demo**, **Broken demo**, **Public yeast**, **Public yeast · missing mate**, or a **Custom folder**. Click **Run validation** and explore the tabs: Delivery summary, Technical results, Sequencing quality, Reports & packages, and History.

**Alternative Conda setup:** `conda env create -f environment.yml` then `conda activate biodataqc`. This environment also installs FastQC 0.12.1.

### Command-line example

The repository includes small, ready-to-use demo fixtures.

```bash
python scripts/validate_dataset.py data/clean
python scripts/validate_dataset.py data/broken --details
```

The clean synthetic example should be `READY`; the deliberately broken one should be `BLOCKED` because an R2 file is missing and one FASTQ record is malformed. CLI exit codes: **0** READY, **1** BLOCKED, **2** INCOMPLETE / export failure.

To save evidence and run history:

```bash
mkdir -p outputs
python scripts/validate_dataset.py data/clean --db outputs/biodataqc.sqlite --json outputs/clean_validation.json
```

For a before/after correction demo using a **new** destination folder:

```bash
python scripts/demo_comparison.py --source data/clean --dataset data/comparison_synthetic_local
```

This saves two runs (a missing read mate followed by its restoration) and demonstrates history comparison. The script refuses to overwrite an existing destination.

### Optional FastQC

The *Sequencing quality* tab invokes the **external FastQC executable** (it is not a Python-only implementation). The current adapter explicitly requires **FastQC 0.12.1** and a working Java runtime. An example Conda installation:

```bash
conda install --override-channels --strict-channel-priority -c conda-forge -c bioconda fastqc=0.12.1
fastqc --version
```

First validate the **Public yeast** dataset as READY, then use *Sequencing quality → Check FastQC installation → Run FastQC*. Reports are generated locally beneath `outputs/`. See [FastQC integration notes](docs/FastQC_Integration.md).

## Data and reproducibility

- `data/clean` and `data/broken`: small synthetic FASTQ deliveries, generated by `scripts/generate_demo_data.py`.
- `data/public_yeast`: public paired-end yeast subset (`SRR6357070`) derived from the **nf-core/test-datasets** project, with source provenance and integrity hashes recorded in its `requirements.json`.
- `data/public_yeast_missing_mate`: deliberately incomplete copy used to demonstrate detection.
- `data/comparison_demo`: sample data for comparing validation runs.

Fixtures are provided for demonstration, **not** for clinical interpretation. Generated reports, databases, FastQC outputs, downloaded caches and package copies belong under ignored `outputs/` and are not part of the tracked source.

## Tests

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

The test suite covers validation, FASTQ handling, SQLite history, comparisons, reports, packaging, UI behavior and FastQC parsing/integration. FastQC-related automated tests use a test fixture rather than requiring a live sequencing run. The full suite requires the Python UI dependencies; a real FastQC invocation additionally requires the external executable.

## Scope and limitations

This is a **personal proof of concept**, not a regulated medical system, laboratory information management system (LIMS), sequencing pipeline, or commercial product. It does not align reads, perform variant calling, trim adapters, or make biological/clinical acceptance decisions. Validation policy is configured for each delivery; a passed result is specific to those rules and the checked file snapshot. Use only authorized data and review outputs before any real-world delivery.
